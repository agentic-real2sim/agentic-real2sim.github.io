---
name: run-code-and-debug
description: This skill should be triggered when the agent is given explicit instruction to run a script, inspect outputs, validate results (and potentially debug).
---

First, either activate conda environment `droid_sim` for running scripts (if the script involves MuJoCo) or use the environment under `.venv/` (if the script involves Newton). Refer to `readme.md` for CLI arguments to pass to the script; but note that if what's instructed in `readme.md` is inconsistent with the script's content, update `readme.md` according to the script. Ask me if you're unsure about path to files (needed as CLI arguments).

If the agent is not given explicit instruction to debug, just conduct a "pilot run" and notify user of the results printed to terminal and artifacts generated; bring up anything that looks like a bug/error. If the agent is explicitly instructed to debug, spawn subagent A to run script and inspect outputs (terminal output and generated artifacts); spawn subagent B to reason about the expected outputs, the current/actual outputs and the difference; the main agent takes in A and B's findings, assesses them in junction with any test plan provided in planning documents (if available), determine what need to be changed and proceed to make changes, and rerun the code. Then A and B conduct their respective tasks again, and the main agent assesses if the issue is resolved. This loop continues until the issue is resolved, but should break when, after over 3 trials of debugging the expected and final results still have significant differences, indicating that the issue might be too hard for the agent to solve on its own and human intervention is needed. In that case, the agent should clearly summarize the issue, what has been tried, and why it thinks human intervention is needed.
